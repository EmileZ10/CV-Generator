# Agent control: instruction and enforcement

The instruction document is `.claude/skills/auto-commit-when-done/SKILL.md`. It tells the agent to commit right after any code change is verified — tests pass, nothing broken — no matter how small the change is. It should not fire when the user says "let me look first" or "don't commit yet," or when a test is still failing.

The enforcement is a PreToolUse hook (`.claude/hooks/block-branch-creation.py`) that blocks any command creating a new git branch, while still allowing `git branch` (just listing) or switching to a branch that already exists. Instruction alone wasn't enough because it took three tries to get the skill to trigger reliably, and even a good instruction is just a strong habit, not a guarantee — the model isn't being negligent, this is non-determinism: the same agent, same prompt, same context, same model can act differently one time out of ten, and a mistake that is expensive to undo cannot settle for a good probability. Branch creation already caused a real problem once on this project, so it can't rely on "probably fine" — it needs something that blocks it every single time, which only a hook can do.
